## 0. 結論（作りやすくする考え方）

**「1枚もの完成品」で作るのをやめ、資料を"部品（モジュール）"に分けて棚に並べ、対象者ごとに組み替える。**

- ①〜⑥は、**強調点・言葉づかい・見せる実績が違うだけ**で、土台の事実（会社概要・技術原理・数値・知財）は共通。
- そこで資料を **A. 共通コア（毎回使う）** と **B. 対象者モジュール（相手で差し替え）** に分解する。
- 1本の配布物 ＝ 「共通コア数枚 ＋ 相手モジュール数枚」を**選んで束ねる**だけ。
- 組み合わせ（①+③+④+⑤ や ⑥+③）も、モジュールを足し引きするだけで完成。

```
［共通コア C1〜C5］＋［相手モジュール Mx, My …］＝ 対象者向け資料
```

## 4. ギャップ（不足・要整備）と次の一歩

- **共通コアの"最新版マスター"が202606止まり** … C1/C2を第2期の数字・体制で更新すると、全対象者資料が一気に最新化される（＝一番効く投資）。
- **④⑤は事例が「あまご/笠岡」1件ずつ** … 実証が増えたら差し替えできるよう、モジュール単位でフォルダ管理。
- **⑥エンドユーザー向けの"1枚チラシ"が商品カタログに内包** … 独立モジュール化すると⑥+③の束ねが楽。
- **表紙・目次・体裁の共通テンプレ**が未整備 … ここを1つ作ると、束ねた瞬間に見た目が揃う。

### ゆきの推奨・次の一歩（ご指示があれば着手）
1. Drive に「**資料モジュール**」フォルダを新設し、C1〜C5／M1〜M6 のサブフォルダに既存PDFを**コピー整理**（原本は動かさない）。
2. **共通テンプレ**（表紙・目次・フッター）を1つ作成 → 以後どの束ねも同じ体裁に。
3. 試作1本（例：⑥+③ or ①+③+④+⑤）を組んで、束ね方の"型"を固める。
