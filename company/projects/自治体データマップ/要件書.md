## 0. 本書の目的

現在アーティファクトとして試作された「日本 自治体データマップ」（単一ファイルのReactアプリ、完全オフライン動作）を、次の3点に発展させるための企画・要件を整理します。

1. **オンライン版**にする
2. **最新の情報を収集できる**形にする
3. **サブスク型アプリ**にする

本書は「何を・どこから・どう作り・いくらかかるか」を意思決定できる状態にすることを目的とし、実装コードは含みません。**事実確認が取れていない点は「要確認」と明記**しています（推測を事実として断定しないため）。

## 1. 現状分析

### 1-1. 試作アプリの良い点

- 47都道府県・1,879自治体を「地方 → 都道府県 → 市区町村」の階層で辿れる、直感的なUI設計ができている。
- 各自治体の詳細カード（JISコード、人口、面積、特産品タグ、農業・畜産の説明、地域の特徴）という**情報の「型（テンプレート）」がすでに固まっている**。これはデータベース設計にそのまま流用できる大きな資産です。
- 完全オフライン動作で、ネット環境なしでも即座に閲覧できる。
- React で作られているため、本番用のWebアプリへ発展させやすい。

### 1-2. 限界（率直な評価）

- **データが概算・ダミー的**である点が最大の課題です。たとえば人口が「約3〜15万人」、面積が「約50〜300km²」といった**幅（レンジ）表示**で、実在の自治体の正確な最新値ではありません。サブスク（有料）で提供するには、この「データの正確さ・最新性・出典の明示」が必須条件になります。
- ブラウザ内でBabelがトランスパイルする試作構成のため、**本番運用向けにビルド（コンパイル）されていない**。表示速度・安定性・SEO・課金導線の面で本番配信には向きません。
- データがコード内に直書きされているため、**データ更新のたびにアプリ本体を作り直す**必要があり、最新化の仕組みがありません。

### 1-3. 結論

UI・情報設計という「器」は完成度が高い一方、中身の「データ」と、それを最新に保つ「仕組み」、そして「課金基盤」が未整備です。本プロジェクトはこの3点を埋める作業と位置づけられます。

## 2. データソース（最新・正確な自治体データの入手先）

実在の公的サービスを調査しました。**重要な注意：地域経済分析システム RESAS の API は 2025年3月24日をもって提供終了**しています（Web版サイト自体は継続）。そのため、RESAS API に依存しない設計が必須です。代替として国土交通データプラットフォーム（MLIT DPF）を候補に加えています。

### 2-1. 主要データソース一覧

| データソース | 取得できる主なデータ | API/形式 | 利用規約・出典表示 | 費用 |
|---|---|---|---|---|
| **e-Stat（政府統計の総合窓口）** | 国勢調査（人口・世帯）、農林業センサス（経営体数・耕地面積・家畜飼養頭数）、作物統計、面積調 等。全国／都道府県／市区町村別 | REST API（仕様3.0版ほか）。要**アプリケーションID**（無料登録）。JSON/XML/CSV。ファイル（Excel等）DLも可 | 出典表示が必要（例「出典：政府統計の総合窓口(e-Stat)」）。加工利用時は加工した旨の表示。詳細は利用規約を**要確認** | **無料** |
| **RESAS（地域経済分析システム）** | 人口構成、産業構造、農業産出額 等（Web版で閲覧可） | **API は2025年3月24日で提供終了**。現在は新システムのWeb画面での閲覧が中心 | Web版の二次利用条件は**要確認** | 無料（API廃止） |
| **国土交通データプラットフォーム（MLIT DPF / mlit-data.jp）** | 都道府県コード・市区町村コード、人口ほか国交省統合データ。RESAS API の代替候補 | **GraphQL API**（単一エンドポイント）。要アカウント登録 | 利用規約を**要確認**（出典表示の要否含む） | 無料（**要確認**） |
| **総務省 全国地方公共団体コード** | 47都道府県・市区町村の団体コード（JISコードの基）と正式名称の全国一覧。**マスタデータの土台** | e-Govデータポータル等でファイルDL（Excel/CSV）。年1回程度更新 | 政府標準利用規約（CC BY 相当）に準拠。出典表示を推奨。詳細**要確認** | **無料** |
| **各自治体オープンデータ／CKAN（data.go.jp、地方公共団体標準データセット）** | 各自治体独自の統計・地域情報。デジタル庁「地方公共団体標準データセット」で様式が標準化 | **CKAN標準API**（メタデータ・データ取得）、CSV等。自治体ごとに整備状況・様式に差 | 自治体ごとにライセンスが異なる（多くはCC BY相当）。個別に出典表示・条件確認が必要 | 原則**無料**（自治体により差） |

補足の一次情報URL：
- e-Stat API トップ https://www.e-stat.go.jp/api/
- 農林業センサス（e-Stat） https://www.e-stat.go.jp/stat-search/files?toukei=00500209
- MLIT DPF API ドキュメント https://www.mlit-data.jp/api_docs/
- 全国地方公共団体コード（総務省） https://www.soumu.go.jp/denshijiti/code.html
- DATA GO JP（CKAN） https://www.data.go.jp/

### 2-2. データソースの役割分担（推奨）

1. **マスタ（骨格）**：総務省「全国地方公共団体コード」＝ 47都道府県・1,879自治体の名称とコードの正本。
2. **人口・面積・農業統計（中身）**：e-Stat API（国勢調査・農林業センサス・面積調・作物統計）。**本プロジェクトの主力データ源**。
3. **補強**：MLIT DPF（RESAS API 代替として、必要に応じ）、各自治体オープンデータ（特産品・地域特徴の裏付け）。
4. **特産品タグ・地域の特徴の説明文**：公的統計だけでは埋まらないため、自治体オープンデータや自治体公式サイト（出典明記）を組み合わせ、初期は編集部（人手）で整備する運用が現実的です。

## 3. 「リアルタイム／最新」の実現方式（正直な説明）

### 3-1. まず前提の共有

「リアルタイム＝毎秒更新」を期待されるかもしれませんが、**公的統計はそもそも毎秒更新されません**。国勢調査は5年ごと、農林業センサスも5年ごと、団体コードは年1回程度の更新です。株価のような常時変動データではないため、「リアルタイム配信」は技術的にも意味を持ちません。

### 3-2. 現実的で誠実な設計

したがって本アプリの「最新性」は、次の仕組みで実現します。

> **公的APIから定期バッチで最新版を取り込み → 自前のデータベースにキャッシュ（保存）→ アプリはそのDBから高速配信**

利用者には常に「出典・更新年月日」を明示し、「いつ時点のデータか」が分かる形にします。これにより「最新の公表値を、正確に、出典付きで提供する」という、有料に値する価値を実現します。

### 3-3. 更新頻度の設計（案）

| データ種別 | 更新頻度 | 取込方法 |
|---|---|---|
| 団体コード（マスタ） | 年1回＋改編時 | バッチ（手動トリガ可） |
| 人口・面積（国勢調査・面積調） | 新統計公表時（数年周期） | 定期バッチ（月次で新規公表を検知） |
| 農業・畜産（農林業センサス等） | 新統計公表時（5年周期＋中間統計） | 定期バッチ |
| 特産品・地域特徴（編集情報） | 随時／四半期見直し | 管理画面から編集 |

運用イメージ：**月次バッチで「新しい公表があるか」を点検**し、あれば取り込む。日次で軽微な整合チェック。ユーザーには「データ更新のお知らせ」を通知（有料機能の候補）。

## 4. システム構成（オンライン化）

### 4-1. 全体像

```
[公的API/DL]        [取込パイプライン]      [DB]         [バックエンドAPI]     [フロント]
e-Stat API      →   定期バッチ         →  PostgreSQL →  REST/GraphQL      →  Webアプリ
MLIT DPF        →   (正規化・出典付与)                                        (ブラウザ)
自治体オープンデータ                        ↑キャッシュ         ↑認証・課金判定
総務省コード                                                    Stripe / 認証基盤
```

### 4-2. 各レイヤーの選択肢と推奨

| レイヤー | 選択肢 | 推奨と理由 |
|---|---|---|
| フロントエンド | 現Reactを本番ビルド（Vite） / **Next.js** / Remix | **Next.js を推奨**。現在のReact資産を活かせ、SEO・サーバー処理・認証・課金導線を1つの枠組みで扱え、後述Vercelとの相性が良い |
| バックエンド／API | Next.js のAPI Routes / 独立Node.js / Python(FastAPI) | 初期は **Next.js API Routes に統合**し小さく始める。取込処理が重くなれば分離 |
| データベース | **PostgreSQL**（Supabase / Neon 等マネージド） | **PostgreSQL を推奨**。1,879自治体×複数指標の構造化データに最適。マネージドで運用負荷を下げる |
| データ取込パイプライン | スケジュール実行（Vercel Cron / GitHub Actions / クラウドのジョブ） | まずは **GitHub Actions か Vercel Cron の月次バッチ**で十分。将来はワークフロー基盤へ |
| 認証 | **Clerk** / Auth0 / Supabase Auth / NextAuth | 小規模なら **Clerk か Supabase Auth**（導入が速い） |
| ホスティング | **Vercel** / Cloudflare (Pages/Workers) / Render | **Vercel を推奨**（Next.js純正・立ち上げが速い）。コスト最適化重視なら Cloudflare、常時稼働のバックエンドが要れば Render も候補 |

### 4-3. 推奨スタック（まとめ）

> **Next.js（フロント＋API）＋ PostgreSQL（Supabase/Neon）＋ Stripe（課金）＋ Clerk/Supabase Auth（認証）＋ Vercel（ホスティング）＋ GitHub Actions（定期取込）**

理由：現Reactの資産を最大限活かしつつ、少人数・低コストで立ち上げられ、後から拡張しやすい組み合わせです。

## 5. サブスク課金の設計

### 5-1. 課金基盤

- **Stripe（Stripe Billing）を推奨**。日本の月額サブスクの標準的選択肢で、Next.jsとの実装例も豊富です。
- 手数料の目安（**要確認・変動あり**）：基本決済手数料 **3.6%** に加え、Stripe Billing の追加手数料（**0.7%程度**）。一部手数料に消費税10%。最新の料率・プラン改定は Stripe 公式（https://stripe.com/jp/pricing ）で**要確認**。

### 5-2. 無料／有料の機能線引き（案）

| 機能 | 無料プラン | 有料プラン（月額） |
|---|---|---|
| 自治体の基本情報（名称・コード・地方階層） | ○ | ○ |
| 人口・面積の最新公表値 | 一部（概要のみ） | ○（詳細・年次推移） |
| 農業・畜産の詳細統計、特産品データ | △（要約のみ） | ○（フル） |
| 自治体の比較（複数選択・並べ替え） | × | ○ |
| データのエクスポート（CSV/Excel/PDF） | × | ○ |
| データ更新通知・お気に入り登録 | × | ○ |
| 広告 | 表示あり（任意） | 非表示 |

価格帯（たたき台・**要決定**）：個人向け 月額500〜1,500円程度、事業者／自治体・農業法人向けに上位プラン。無料お試し期間の設定も検討。

### 5-3. 認証と課金連携

- 会員登録／ログイン（メール＋パスワード、またはGoogleログイン）。
- 決済成功のWebhookを受けて「有料フラグ」をDBに反映し、機能の出し分けを行う。
- 解約・返金・領収書発行はStripeの標準機能を利用。特定商取引法に基づく表記など、**日本の商用要件は要確認**。

## 6. MVP（最小構成）と段階的ロードマップ

### STEP 1 ─ MVP：正確な「人口・面積」オンライン版（無料で公開）
- 総務省コードで全1,879自治体のマスタを整備。
- e-Stat から**人口・面積の正確値**を取り込み、出典・更新日を明示。
- 現UIをNext.jsで本番ビルドし、Vercelで公開。
- 目的：まず「概算ではない正確なデータ」を世に出し、反応と需要を見る。

### STEP 2 ─ 農業・畜産データと課金の導入
- 農林業センサス等から農業・畜産統計を取り込み、特産品データを編集整備。
- Stripe＋認証を導入し、無料／有料の線引きを実装（比較・エクスポート・更新通知を有料に）。

### STEP 3 ─ 最新化の自動化と付加価値
- 月次の定期取込バッチを本格運用（新統計公表の自動検知・通知）。
- 上位プラン（事業者・自治体向け）、API提供やレポート機能など収益の柱を追加。

## 9. 法務・データ利用上の留意点

- **出典表示は必須**。e-Stat・総務省コード等の政府データは、二次利用時に出典の明記が求められます（例「出典：政府統計の総合窓口(e-Stat)を加工して作成」）。各ソースの利用規約に従って正確に表示します。
- **加工・再配布の可否**は各ソースで異なります。政府標準利用規約（CC BY 相当）は商用利用・加工・再配布を広く認めますが、**個別条件は必ず一次情報で要確認**。特に自治体オープンデータはライセンスが自治体ごとに異なります。
- **RESAS API は2025年3月24日に提供終了**しているため、RESAS APIに依存する設計・記述は行いません（本書の他章と整合）。
- **有料再配布**（サブスクで統計を提供）が各規約上問題ないかは、収益化前に**要確認**（多くの政府データは商用可ですが、明文で確認します）。
- **特産品・地域の説明文**を自治体サイト等から引く場合、著作権・出典に配慮し、事実データ中心に構成します。
- **個人情報保護・特定商取引法・消費税**など、日本の商用サービス運営上の法務要件は、公開前に専門家確認を推奨（**要確認**）。

いずれも「断定できない点」は上記のとおり明示しました。実装フェーズで一次情報にあたり、確定させていきます。
